# AI model consolidation implementation status (2026-09-24)

The code changes are complete in this working tree but are **not deployed**. The original [audit](./ai-model-audit.md) and [plan](./ai-model-cleanup-plan.md) remain the decision record. This document records what was actually implemented and what still blocks rollout.

## Implemented

- Central model policy: `google/gemini-3.8-flash` for food text/vision/reasoning, `typesafe/jev-1.13` for finite choices, `gpt-image-2.5-flare` for new icons. Unsupported food/decision overrides fail closed. Existing BGE/ADA vector storage and retrieval were left intact.
- Removed the Haiku/Anthropic, GPT-3.5 instruct, old GPT-4 extraction/matching, Vertex, Groq, Fireworks, Perplexity, DALL-E 3 and ClipDrop code paths, as well as their unused dependencies and related experiments. Existing OpenAI SDK remains for ADA embedding compatibility; the Image API remains for icons.
- Text and image food extraction, time inference, serving inference, local candidate matching and the existing food agent use Flash through OpenRouter. External finite-choice matching uses Jev; exact matches still bypass the model.
- Removed the remaining Vertex/Llama serving aliases and debug-only database probe. The opt-in synthetic benchmark now reads the same model constants as production and hashes the current matcher file.
- Category classification is now a two-stage Jev decision (family, then leaf) over the 403 named categories. The flat 404-option request returned HTTP 400; Jev's documented choice limit is 255. Both stages require confidence at least 0.9, and unknown, cross-family or low-confidence decisions abstain. An inherited blank `G-3-7` line was removed from the taxonomy source; it was never a selectable category. Categorization is queued after inserting a food, and the validated worker no longer needs `FOOD_CATEGORY_JEV_ENABLED`. The maintenance command still previews by default and writes only with `--apply`.
- Added a guarded migration for the old duplicate `F-8-3` Tomatoes code. It changes only rows explicitly named Tomatoes to the new `F-8-11` code. It has **not been applied**.
- Replaced the Serper scraping path with OpenRouter's Exa web-search tool for final online nutrition fallback. Work is bounded to two searches and requires a cited URL and positive serving weight plus calories/fat/carbs/protein. Missing evidence abstains rather than inserting guessed values.
- Icon generation requests a native transparent PNG from the current Image API; icon reuse and asynchronous decoration remain.

## Validation performed

- `npx tsc --noEmit --incremental false`: passed.
- `node --test tests/*.test.cjs`: 202/202 passed, including offline taxonomy coverage, category queue idempotency and Exa-response tests.
- `npm run lint`: passed with four pre-existing React Hook dependency warnings in unrelated UI components.
- `npm run build`: completed. Existing Redis hostname was unreachable in this sandbox during static-page collection, and existing BullMQ/Browserslist/React lint warnings remain in its log.
- Four synthetic, no-write live Flash extraction requests completed in 807–1,085 ms each and preserved separate coffee/Fairlife milk, chicken/oil-and-vinegar dressing, Starbucks latte/apple, and coffee/Fairlife 2% milk components. These are small functional checks, not throughput benchmarks.
- Two earlier synthetic Exa protocol requests confirmed the server tool returned citation annotations and sometimes fenced JSON. A broader 40-case, no-write public-food coverage check accepted **21/40** (11/20 generic, 10/20 branded), with observed per-request p50 **4.98 s** and p95 **7.99 s**. Several accepted results cited blogs, retailers or other secondary sites, and common foods such as olive oil, whole milk and almonds abstained. [Per-case evidence](./ai-model-audit-evidence/exa-coverage-2026-09-24.json). A separate Fairlife diagnostic showed its own cited page lacked a sourced weight in grams and correctly abstained. A higher-recall `deep-lite` configuration on ten of the fast-mode failures accepted **0/10** and took roughly 10–13 seconds per request. A temporary Serper-snippets-plus-Flash probe on those ten accepted **4/10**, but most citations were also secondary; it was not the original Serper scraper/GPT-4 baseline. These outcomes do not pass the source-quality/coverage gate and are not a demonstrated win over the old Serper path.
- Two no-write synthetic banana icon requests to `gpt-image-2.5-flare` succeeded in 12–13 seconds each and returned 1,024×1,024 PNGs with real transparent pixels. The revised prompt produced a clean silhouette when composited on white. The five-type visual gate remains open.
- The user explicitly approved sending Amino's nonconfidential taxonomy and synthetic food names to OpenRouter for no-write Jev tests. Across four final sets totaling **226 synthetic cases**, the production 0.9 cutoff accepted **187 correct, 0 wrong**, and abstained on 39; all **18 vague names** abstained. Among the 208 classifiable foods, accepted coverage was **187/208 (89.9%)**. The four per-set p50 latencies were 363–430 ms and p95 latencies were 494–546 ms, with no unavailable responses and approximately **$0.022** aggregate reported cost. These are small synthetic accuracy/latency checks, not a real-catalogue or throughput benchmark. Per-case results: [holdout](./ai-model-audit-evidence/jev-category-holdout-eval-2026-09-24.json), [challenge](./ai-model-audit-evidence/jev-category-challenge-eval-2026-09-24.json), [fresh](./ai-model-audit-evidence/jev-category-fresh-eval-2026-09-24.json), and [preservation](./ai-model-audit-evidence/jev-category-preservation-eval-2026-09-24.json). The first fresh run found dried apricots wrongly accepted as fresh apricots at 0.8; [pre-refinement evidence](./ai-model-audit-evidence/jev-category-fresh-before-refinement-2026-09-24.json) is retained. A generalized dried-fruit rule and the stricter 0.9 cutoff resolved that observed error on rerun.
- A direct smoke check of the production-default classifier returned `E-6-6` for synthetic dried mango, `A-3-2` for Greek yogurt and `null` for the vague name “bar.” It made no database writes.
- Offline tests verify that the two-stage decision contains every canonical category exactly once and stays within the 255-choice API limit for every family.

## Rollout gates still open

1. **Jev production rollout:** The taxonomy-only synthetic evaluation is complete and the user's explicit approval resolved the earlier automatic approval block. The worker is enabled in this working tree, which is **not deployed**. The duplicate-ID Tomatoes migration has not been applied; review existing ID/name pairs and apply that migration as part of the release. A controlled production shadow or sampled catalogue review is still needed because synthetic names cannot establish real-world category accuracy.
2. **Exa search quality:** The 40-case coverage run failed the source-quality and usability gate: 21/40 accepted, with multiple secondary citations. Improve search evidence and compare end-to-end accuracy and cost against the previous Serper route before rollout. This checkout should not be deployed as a search replacement yet.
3. **Image quality:** The banana sample verified API access and alpha. Check the other representative icon types before enabling production icon generation. Storage/linking and cost also need a controlled no-bulk trial.
4. **End-to-end performance:** The synthetic extraction timings are encouraging but do not establish tokens/second, p95, photo/label behavior or full meal-resolution latency. Run the plan's longer functional and speed benchmark before rollout.
5. **Configuration:** Ensure the deployment has `OPENROUTER_API_KEY` (or its supported alias) and `OPENAI_API_KEY`; local `.env.local` may need the OpenRouter secret. No keys are written to this repository.

No schema or deployment changes were applied to a live database, and no production user records were sent to a model during this implementation session.
